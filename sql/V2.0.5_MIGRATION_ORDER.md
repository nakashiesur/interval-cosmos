# INTERVAL COSMOS v2.0.5 — Database build order

> RELEASE STATUS: canonical Phase 1 restoration, fresh empty-project structural verification, and database-level functional smoke are PASS. Browser/runtime verification remains before release. See Issue #6.

This document records the deterministic build order for the current v2.0.5 development database.

## 0. Phase 1 base schema

The canonical Phase 1 source has been restored byte-for-byte into eight ordered files under `sql/base-v2.0.5/`. Root `supabase_setup.sql` is a psql include manifest for those eight parts.

Canonical SHA-256:
`1949b4dc9aed25c72e93ebce746af363ef51fb771a64ae73817a85be385bba23`.

## 1. Canonical avatar catalog

`sql/avatar-catalog-v2.0.5.sql`

Canonicalizes the 12 student avatar IDs plus staff-only `teacher`, retires the old `default` placeholder, and makes the database column default `nova`. Final artwork remains a Phase 11 task.

## 2. Device linking

`sql/device-link-v2.0.5.sql`

Adds the six-digit, expiring, one-time, source-device-confirmed multi-device flow.

## 3. Account recovery

`sql/account-recovery-v2.0.5.sql`

Adds recovery-code hashing, lockout, recovery status, recovery linking, and registration-time recovery setup.

## 4. Account avatar fallback compatibility

`sql/account-avatar-default-v2.0.5.sql`

Corrects the recovery-layer `create_player_account()` fallback so omitted/empty avatar values resolve to `nova` instead of the retired `default` placeholder.

## 5. Progression / MY COSMOS

`sql/progression-v2.0.5.sql`

Seeds achievements/titles/frames/daily missions and adds progression/profile RPCs.

## 6. Assignments base RPC layer

`sql/assignments-v2.0.5.sql`

Adds assignment creation/student/admin result RPCs.

## 7. Admin-only assignment authorization

`sql/assignments-admin-only-v2.0.5.sql`

Restricts assignment management to `is_admin=true` rather than ordinary staff status.

## 8. Multi-mode assignments

`sql/assignments-multimode-v2.0.5.sql`

Adds `allowed_modes`, per-mode bests, multi-mode submission/results, and this-run vs previously-achieved state.

## 9. Admin learning dashboard

`sql/admin-dashboard-v2.0.5.sql`

Adds admin overview and per-student aggregate RPCs.

## 10. Staff self-registration / private identity

`sql/staff-self-registration-v2.0.5.sql`

Adds staff self-registration, private `real_name`, staff course selection, fixed teacher avatar behavior, and private identity RPCs.

## 11. Admin player/account management

`sql/admin-player-management-v2.0.5.sql`

Adds admin-only management for profile/course/avatar editing, suspension/restore, ranking unpublish/delete, and the service-role-only application-row delete used by the server-side delete function.

Complete Auth-user deletion is handled by `supabase/functions/admin-delete-player/index.ts`; the service-role key is never placed in browser code.

## 12. Security hardening

`sql/security-hardening-v2.0.5.sql`

Removes unintended exposed execution on internal trigger/event-trigger helpers and fixes mutable `search_path` on the timestamp trigger helper while preserving intended browser-callable RPCs.

## Deterministic order

For a fresh v2.0.5 build, use this exact order:

1. `supabase_setup.sql`
2. `sql/avatar-catalog-v2.0.5.sql`
3. `sql/device-link-v2.0.5.sql`
4. `sql/account-recovery-v2.0.5.sql`
5. `sql/account-avatar-default-v2.0.5.sql`
6. `sql/progression-v2.0.5.sql`
7. `sql/assignments-v2.0.5.sql`
8. `sql/assignments-admin-only-v2.0.5.sql`
9. `sql/assignments-multimode-v2.0.5.sql`
10. `sql/admin-dashboard-v2.0.5.sql`
11. `sql/staff-self-registration-v2.0.5.sql`
12. `sql/admin-player-management-v2.0.5.sql`
13. `sql/security-hardening-v2.0.5.sql`

Do not reorder these migrations unless the dependency chain is re-verified.

## Release-quality build path

Use:

`DATABASE_URL='postgresql://...' bash scripts/apply-v2.0.5-db.sh`

The runner applies all 13 steps with shell stop-on-error and `psql -v ON_ERROR_STOP=1`.
