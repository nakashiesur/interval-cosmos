# INTERVAL COSMOS v2.0.5 — Database build order

> RELEASE STATUS: the Phase 1 base has been restored from the canonical 1,571-line source. Fresh empty-project verification is still required before release. See Issue #6.

This document records the deterministic build order for the current v2.0.5 development database.

## 0. Phase 1 base schema

The canonical Phase 1 source has been restored byte-for-byte into eight ordered files under `sql/base-v2.0.5/`. Root `supabase_setup.sql` is now a psql include manifest that applies those eight parts in order.

The release gate verifies the concatenated restored parts against the canonical SHA-256:
`1949b4dc9aed25c72e93ebce746af363ef51fb771a64ae73817a85be385bba23`.

Creates the base catalogs, players/devices, public profile mirror, assignments/play sessions/ranking bests, progression tables, RLS, and initial RPCs.

## 1. Canonical avatar catalog

`avatar-catalog-v2.0.5.sql`

Canonicalizes the 12 student avatar IDs used by the v2.0.5 registration UI plus staff-only `teacher`. The visual art remains temporary until Phase 11.

## 2. Device linking

`device-link-v2.0.5.sql`

Adds the 6-digit, existing-device-confirmed multi-device flow.

## 3. Account recovery

`account-recovery-v2.0.5.sql`

Adds student-controlled recovery-code hashing, lockout, and no-existing-device recovery.

## 4. Progression / MY COSMOS

`progression-v2.0.5.sql`

Seeds achievements/titles/frames/daily missions and adds progression evaluation/profile RPCs.

## 5. Assignments base RPC layer

`assignments-v2.0.5.sql`

Adds assignment creation/student/admin result RPCs against the base assignment tables.

## 6. Admin-only assignment authorization

`assignments-admin-only-v2.0.5.sql`

Changes internal assignment management authorization from account type to `is_admin=true` only.

## 7. Multi-mode assignments

`assignments-multimode-v2.0.5.sql`

Adds `allowed_modes`, per-mode assignment bests, multi-mode create/submit/status/result RPCs, and this-run vs previously-achieved state.

## 8. Admin learning dashboard

`admin-dashboard-v2.0.5.sql`

Adds read-only admin overview/student-detail aggregate RPCs.

## 9. Staff self-registration / private identity

`staff-self-registration-v2.0.5.sql`

Adds staff self-registration, private `real_name`, staff course selection, teacher-avatar behavior, and private identity RPCs.

## 10. Admin player/account management

`admin-player-management-v2.0.5.sql`

Adds admin-only RPCs for:
- reading management state,
- editing student profile/course/avatar,
- suspension/restore,
- ranking unpublish,
- ranking-best deletion,
- the service-role-only final application-row deletion used by the server-side delete function.

Complete Auth-user deletion is intentionally handled by `supabase/functions/admin-delete-player/index.ts`; the service-role key is never placed in browser code.

## Deterministic order

For a fresh v2.0.5 build, use this exact order:

1. `supabase_setup.sql`
2. `sql/avatar-catalog-v2.0.5.sql`
3. `sql/device-link-v2.0.5.sql`
4. `sql/account-recovery-v2.0.5.sql`
5. `sql/progression-v2.0.5.sql`
6. `sql/assignments-v2.0.5.sql`
7. `sql/assignments-admin-only-v2.0.5.sql`
8. `sql/assignments-multimode-v2.0.5.sql`
9. `sql/admin-dashboard-v2.0.5.sql`
10. `sql/staff-self-registration-v2.0.5.sql`
11. `sql/admin-player-management-v2.0.5.sql`

Do not reorder these migrations unless the dependency chain is re-verified.

## Release-quality build path

Use:

`DATABASE_URL='postgresql://...' bash scripts/apply-v2.0.5-db.sh`

The runner applies the eleven steps above with stop-on-error behavior.

## Fresh-build verification

Before release, verify on an empty test project:
- expected tables/RLS,
- current avatar catalog,
- student registration,
- recovery and PIN linking,

- ranking publication,
- multi-mode assignments,
