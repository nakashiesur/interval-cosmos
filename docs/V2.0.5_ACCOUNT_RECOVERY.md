# INTERVAL COSMOS v2.0.5 — Phase 2.5 Account Recovery

## Why this exists

The browser uses Supabase anonymous auth as a device identity. Clearing cookies/site data removes the local auth session. Player data itself remains safe in `players`, but if every linked device loses its session, the student previously had no self-service path back to that player.

Phase 2.5 adds a durable recovery credential owned by the student.

## Two different device flows

### 1. A logged-in device still exists
Use the existing 6-digit one-time PIN flow.

- PIN expires after about 5 minutes
- new device enters PIN
- existing device must approve
- both devices remain linked

### 2. No logged-in device remains
Use self-service account recovery.

- enter student number
- enter the recovery code chosen at registration
- current anonymous auth device is linked to the existing player
- all player data remains the same

This is intended for cookie/site-data deletion, browser reset, device loss, and similar cases.

## Student-selected recovery code

Students choose their own recovery code during initial registration.

Rules:

- 8–20 characters
- ASCII letters and digits only
- must include at least one letter and one digit
- case-insensitive (`piano2026` and `PIANO2026` are equivalent)
- cannot be exactly the student number
- entered twice on registration

A logged-in student can change the code later from SETTINGS → Account recovery.

## Storage and security

The plaintext code is never stored.

`player_recovery_credentials` contains:

- player ID
- bcrypt hash from pgcrypto
- failed attempt counter
- temporary lock timestamp
- update timestamp

The table has RLS enabled and no client read/write privileges. Only SECURITY DEFINER RPCs can access the hash.

Five consecutive wrong recovery attempts trigger a 15-minute recovery lock. Normal already-linked devices are not logged out by this lock.

## RPCs

- `set_my_recovery_code(text)` — set/change own code while logged in
- `get_my_recovery_status()` — tells the current student whether a code is configured
- `recover_student_account(student_number, recovery_code)` — link current anonymous auth to the existing player
- `create_player_account(...)` — new v2.0.5 signature requires a recovery code at registration

## Existing players

Players created before this patch have no recovery credential until they set one in SETTINGS. They continue to work normally, but self-service recovery is unavailable until a code is configured.

The current development `test` account should therefore set a recovery code immediately after the patch is applied.

## Recovery test required before release

1. Set a recovery code on the test account.
2. Confirm existing player state (student number, COSMOS PT, frame, history).
3. Clear cookies/site data for localhost.
4. Open INTERVAL COSMOS and obtain a new anonymous auth session.
5. Choose existing account → recovery.
6. Enter student number + recovery code.
7. Confirm the same player returns.
8. Confirm COSMOS PT, frame, learning history and ranking state are unchanged.
9. Confirm five wrong attempts cause a temporary recovery lock.
