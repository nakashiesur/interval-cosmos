# v2.0.5 Pre-release hardening

## 1. Supabase client unification — IMPLEMENTED / FINAL BROWSER CHECK REQUIRED

実ブラウザのDevToolsで以前、以下の警告を確認。

`Multiple GoTrueClient instances detected in the same browser context.`

### 原因

認証を所有する `cloud.js` とは別に、recovery / progression等が追加のSupabase clientを生成していた。

### 対応済み

`supabase-singleton-v205.js` を `cloud.js` より前に読み込み、同一Project URL / keyに対する `createClient()` をブラウザコンテキスト内で1インスタンスへ統一。

- `cloud.js` が最初に生成したclientを共有
- 後段モジュールが `createClient()` を呼んでも同一clientを返す
- Assignments / Admin Dashboardは共有singletonを明示利用
- 認証storage ownerを複数生成しない

### リリース前の実ブラウザ確認

1. 既存学生アカウントの自動ログイン
2. 6桁PINによる別端末追加
3. 学籍番号＋復旧コードによる自己復旧
4. ランキング取得・公開
5. 学習履歴取得
6. MY COSMOS取得
7. 実績・デイリー進行
8. 代表実績の保存
9. Assignments / Admin Dashboard
10. DevTools Consoleに `Multiple GoTrueClient` 警告が出ないこと

多くは実機テスト済み。最終リリース候補でConsole警告をもう一度確認して閉じる。

## 2. Root `supabase_setup.sql` — RELEASE BLOCKER

`v2.0.5-dev` のroot `supabase_setup.sql` は、過去のリポジトリ編集事故により現在プレースホルダ内容になっている。

現行Supabase DBは正規SQLで構築済みのため、**現在動いているDBやゲーム機能には影響しない**。ただし、新規環境を再構築するための配布物としては不完全なのでmainへ出す前に必ず修復する。

正規のPhase 1元SQLは会話添付 `interval-cosmos-v2.0.5-supabase-setup.sql` として保全済み。さらに現行DBへは以下の追加パッチが適用されているため、最終的には再構築手順を一本化する。

- `sql/device-link-v2.0.5.sql`
- `sql/account-recovery-v2.0.5.sql`
- `sql/progression-v2.0.5.sql`
- `sql/assignments-v2.0.5.sql`
- `sql/assignments-admin-only-v2.0.5.sql`
- `sql/assignments-multimode-v2.0.5.sql`
- `sql/admin-dashboard-v2.0.5.sql`

### Release条件

- root `supabase_setup.sql` を正規内容へ復元
- 現在の追加パッチを含むfresh-build手順を確認
- 新規空DBを想定した静的検証または実DB検証を行う

## 3. Offline queue — NOT YET IMPLEMENTED

Service Workerによりアプリ本体のオフライン起動基盤はあるが、ランキング／課題の送信失敗をローカルキューへ保存し、オンライン復帰後に再送する機能は未実装。

これは `client_event_id` による重複排除、ランキング公開確認、課題モード別BEST、実績評価まで跨ぐため、無人状態での差し込みは行わない。

専用回帰テストができるタイミングで実装する。
